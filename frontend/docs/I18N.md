# Internationalisation and RTL

The UI ships in Hebrew and English. Hebrew is the default and the RTL case; English is the source locale,
so an untranslated build reads as the code does.

## The two kinds of text

- **UI chrome is translated** — buttons, labels, toasts, modal copy, error wording this app authors.
- **Data is never translated.** Course, lecture and material names render verbatim under `dir="auto"`, so
  each lays itself out by its own first strong character rather than the page's direction.

The `Other` bucket for a blank Moodle heading looks like data but is chrome; its literal is also a
section's run key, so `OTHER_SECTION` stays untranslated and `sectionTitle()` translates it at render.

Dates and durations are the known gap: `shared/utils/format.ts` hardcodes English ordinals, `en-GB` and
`5m 30s`, so the Hebrew UI reads `10th July`. It is chrome that should be translated and is not.

## Service failures — `shared/i18n/serviceErrors.ts`

Every failure a service reports carries a stable machine `code` and a flat `params` object beside its English
prose; the vocabulary is [../../docs/ERROR-CODES.md](../../docs/ERROR-CODES.md), and the sentences are ours.
The module is a plain record of code → message descriptor; `resolveServiceError` fills the row with the
failure's params and returns `{headline, detail}`, which `shared/components/ServiceError` renders and
`serviceErrorText` flattens for a `title` attribute. Params are named values, never sentence fragments —
Hebrew orders them differently. A `null` param is dropped, so it picks a message's `undefined` clause exactly
as an absent one does.

**A code with no row falls back to the service's prose**, and so does a failure with no code at all. That is
a supported state, not a bug: a service may add a failure before the catalog catches up, and every
developer-facing code in the root doc is deliberately row-less. Rows are written as raw ICU inside
`msg({ message: … })` rather than a tagged template — a template bakes its own `values` into the descriptor,
and `i18n._` lets those win over the ones passed at resolve time.

**Third-party text is never translated.** ffmpeg's stderr, a Gemini message, a TeX error — it rides as the
reserved `detail` param and renders verbatim beneath the translated headline, direction-isolated (see RTL
below). `latex_error` is the same shape with the engine's own words arriving as named params rather than
under `detail`.

A refused request reaches all this as `RequestError` (`services/http.ts`), which carries the body's code and
params; `shared/utils/failure.ts` is the one funnel from a thrown value to a toast.

## Runtime — `services/i18n.ts`

`resolveLocale(stored, language)` is pure: a stored choice wins, then any language not starting with `en`
means Hebrew. `initialLocale()` feeds it `localStorage['fast-study:locale']`, then the OS language off the
bridge (`electron/docs/RENDERER.md`), then `navigator.language` — also when the bridge answers `''`, which
is Chromium failing to read the OS locale and would otherwise resolve to Hebrew. `activateLocale` loads
and activates the catalog and sets `document.documentElement.lang` and `.dir`; that `dir` write is the
single switch that flips the layout.

Only an explicit pick is stored (`chooseLocale`, called by the switcher): persisting the boot guess would
stamp `he` once and ignore the OS or browser language forever. The language is `localStorage` only —
per-browser, reaching no service and no `.env`. Both storage calls are wrapped, since access throws with
cookies blocked.

`main.tsx` awaits activation before the first render — Lingui throws with no active catalog — and falls
back to English if that fails, since a rejection there skips `render` and leaves a blank page the error
boundary cannot catch. `src/test-setup.ts` activates English for the same reason.

`LanguageSwitcher` (sidebar footer) labels each language by its endonym, never translated; only its
`aria-label` is.

## Adding a string

Macros come from `@lingui/core/macro` (`t`, `plural`, `msg`) and `@lingui/react/macro` (`Trans`, `Plural`,
`useLingui`); there is no `@lingui/macro`. In JSX use `<Trans>`/`<Plural>`; in an attribute,
`useLingui().t`; outside a component, the core `t`, which reads the active catalog. A module-level table
(`constants/pipeline.ts`, `constants/overview.ts`, `RecordingRow`'s `RESOLVED_LABEL`) uses ``msg`…` ``,
since it is built before any locale exists; the render site resolves it with `t(descriptor)`.

- **Never splice a translated fragment into another message** — the hole's grammar changes with what
  fills it. Write two whole sentences instead (`notFound.ts`, `materialIndicator.ts`).
- **Count with `plural`/`<Plural>`, never `n === 1 ? …`.** Hebrew has `one`, `two` and `other`, and CLDR
  has revised that set before — `services/resolveLocale.test.ts` checks against `Intl.PluralRules`.

## The extract loop

`npm run extract` updates `src/locales/{he,en}/messages.po` and prints a per-locale missing count; **zero
missing for both is the definition of done**. Hebrew goes in `he/messages.po`; `en` fills itself. `npm run
compile` is only for a build outside Vite, whose plugin compiles `.po` on the fly.

To retire a string, run plain `extract` and hand-delete its `#~` block from both catalogs. Never
`--clean`: it prunes every obsolete entry at once and buries the real diff.

A Hebrew translation may carry more plural categories than a bare-`other` English source; that is
correct, not drift.

## Adding a locale

Add it to `lingui.config.ts` and to `LOCALES` and `CATALOGS` in `services/i18n.ts` (a literal import, so
the bundler sees it), extend `isRtl` if it is right-to-left, add its endonym to `LanguageSwitcher.tsx`'s
`LABELS`, then extract and translate.

## RTL

Every direction-sensitive declaration in `src/**/*.css` is logical (`margin-inline-start`,
`inset-inline-end`, `text-align: start`), so direction follows `document.dir` with no `[dir="rtl"]`
override anywhere. A `margin-left` grep misses asymmetric four-value shorthands, `translateX`, single
corner radii, `box-shadow` x-offsets and `row-reverse` — check those by eye. The two exceptions are
`ErrorBoundary.css`, which pins `direction: ltr` on the stack trace and the report path, and
`ServiceError.css`, which pins it on a failure's third-party detail. Both also set `unicode-bidi: isolate`,
so English cannot reorder the Hebrew sentence around it.

A glyph that points somewhere must flip too. Copy that names a direction is translated as copy (`← Back`
is `→ חזרה`); a glyph from state goes through `shared/components/Chevron.tsx`, which reads the locale via
`useLingui` so a switch re-renders it. `isRtl` is the single decision. `react-toastify`'s CSS is
physical and its `rtl` prop does not move the container, so `App.tsx` picks the corner from `isRtl`.

## Names on disk are language-agnostic

`features/lectures/utils/nextName.ts`'s suggestion becomes a directory, so it infers the prefix from the
course's own children (`הרצאה 3` → `הרצאה 4`) rather than matching `Lecture`; only an empty course falls
back to a translated default. `features/downloads/utils/nameFromTitle.ts` follows the same rule.

That fallback is the one translated string that lands on disk, so it carries `context: 'directory name'`
and never shares a msgid with the identical button label — a translator shortening the button must not
rename directories.

Both parsers assume a course holds only indexed sessions: a stray `סיכום 2024` parses and its year then
drives every suggestion. Deliberately unguarded; the layout has no room for such a name.

`downloader/extension/regular/popup.js` mirrors `suggestName` with an English-only regex, so a
Hebrew-named course gets `Lecture 1` from it. Out of scope: non-English courses were never supported there.
